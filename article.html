How Our Little Browser Engine Works

One HTML file, one stylesheet, and a few thousand lines of Java.

1. Parsing

Every web page starts life as a string of characters. The SimpleHtmlParser walks that string character by character, building a tree of element and text nodes along the way.

Attributes are collected, void elements are recognized, and whitespace is collapsed. When the dust settles we have a DOM tree, ready for the next stage.

“You can't build a browser without parsing — it's the front door of the whole pipeline.”

2. Styling

CSS selectors are matched right-to-left against the DOM tree. The engine understands:

  • • descendant, child, adjacent and general sibling combinators
  • • IDs, classes and element tags, with real specificity
  • • structural pseudo-classes such as nth-child and first-of-type
  • • the !important cascade, layered on top of inheritance

Styles are computed once and stored on every element, so the layout stage can read them straight off the DOM.

3. Layout

Blocks stack vertically, margins collapse, and auto margins center boxes horizontally. Inline text is measured with real font metrics and wrapped into lines as it overflows.

margin: 0 auto — the classic centering trick, implemented properly.

Anonymous block boxes appear whenever inline content shows up between blocks, exactly like a real browser. The result is a tree of boxes, each with a final position and size.

4. Painting

Finally a Renderer paints backgrounds, borders and text onto an image using Java AWT. Add the --boxmodel flag and you get a debug overlay showing the margin, border, padding and content areas of every box.
